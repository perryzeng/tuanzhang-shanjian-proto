## Persona Agent 完整形态（V16，默认落地）

一句话：**一个 Agent + 三个支撑面 + 两个初始化。**
对话负责「今天做什么」，素材/看板/团队负责「要深入的时候去哪」，引导负责「第一次怎么开始」。

| 一级 | 页面 | 承担什么 |
|---|---|---|
| 小剪 | `A8` | AI 先开口：昨日数据 / 素材新进 / 团队任务 / 该跟的人，四种卡串一条对话 |
| 作品 | `A8.4` / `A8.4.1` / `A8.4.2` | 时间轴 + 概要；详情四个 tab，总览用**横条漏斗**排内容侧五项（打开次数/完播数/点赞数/互动数/分享数）+ 完播率/平均停留/打开人数/平均访问次数，**不问价成交**；「按这个结构再剪一条」回小剪首页。**三个平台入口** → 整屏还原该平台播放页（皮肤在 `js/skins.js`，落地页 L1 共用）→ 改互动数屏上立刻变 → 底部**确定生成 / 分享朋友圈**两键 → 生成评论 → 调起微信（朋友圈/好友/群）→ 发表 |
| 客户 | `A8.2` / `A8.2.1` | 每位客户：**从哪条内容来的 / 卡在哪 / 怎么开口**；档案页给判断、轨迹和三条现成话术 |
| 小组 | `A8.3` | 只做成员视角，三块：**组长公告 / 派给我的活 / 组里动态**（谁交了、谁被夸、谁掉队） |
| 我的 | `A6.1` | 人设 IP / **我的素材（`A8.1` 降到这里的入口）** / 声音 / 形象，右上角头像进 |
| 引导 | `A8.0` | 三问 → 自动写人设 prompt + 7 天排期 |

**三个关键决定**

1. **素材不按库分 tab。** 个人/团队/平台是「归属」，用户心里想的是「我要一条讲成分的素材」。
   所以进来先看到三个状态（能用 316 / 待处理 12 / 有问题 5），来源只是筛选 chip。
2. **素材页的主体是积木，不是原始料。** 用户剪片时要的是「一段 14 秒讲磷脂含量的口播」，
   不是「三个月前传的那条 3 分钟视频」。原始料收进 `A8.1.1`（右上角「我丢的」），只在丢和查的时候进。
   积木上标「被用过几次」——团队里同一条片段用太多次，观众会认出来是批发的。
3. **看板与客户合并。** 团长看的顺序永远是「这周怎么样 → 谁在看我 → 该找谁」，分成两个 tab 中间就断了。
4. **素材的单位是片段。** 一条 3 分钟视频拆成 6 个 8~20 秒片段，逐段打分打标（`A8.1` 详情页）。
   团长真正用的是「一段讲成分的」，不是「那条视频」。

**新人引导的终点不是填完，是拿到两样东西**：一段可改的人设 prompt（AI 写每句台词前先读它）+ 一份 7 天排期（第 1 条就标着「今天」）。

## 对话版 A6（V15 · AI 原生，保留对照）

这一版是另一条路：**没有首页、没有 tab、没有模块，整个产品只有一条对话和一个输入框。**

不是把功能塞进聊天窗口，而是让 AI 主动发起下一步：
早上它先说三件事（昨天多少人来、今天该出哪条、谁该跟），用户回一句就往下走。

**一条完整链路，全程不跳页**

| 步骤 | 用户做的 | AI 做的 |
|---|---|---|
| ① 开场 | 看 | 汇报昨日数据 + 今天该出第 5 条 + 2 条没发 + 阿梅该跟 |
| ② 剪 | 说「剪一条」 | 连问三句：讲什么 / 给谁看 / 多长 |
| ③ 出稿 | 看一眼 | 给**脚本卡**：3 段，每段一个画面槽 + 一句台词，台词可直接改 |
| ④ 出片 | 点「就这样，出片」 | 给视频卡 + 问发哪儿 |
| ⑤ 分发 | 选朋友圈 | 给文案 + 带「你·这条·渠道」标记的链接 |
| ⑥ 回传 | 复制去发 | 20 分钟后主动汇报：12 人点开、3 个看完、李姐停在「怎么买」，建议回她 |

**首次引导（A6.0）四个问题，全是对话，没有一个表单控件**：
行业（决定话术库和合规红线）→ 内容类型（决定结构模板）→ 人设（决定语气）→ 素材（决定能不能真出片）。
答完立刻给第一条选题，不让人空手走。

**四个抽屉**（◎ 唤出，不占主界面）：
`A6.1 我是谁`（IP 设定：行业/人设/人群/口头禅/不能说 + 声音 + 形象）、
`A6.2 我的素材`（私有原料包：出镜/产品/场景/顾客反馈）、作品（E2）、客户（G3.1）。

> **A1.2 和 A6 是两条并存的路，不是替代关系。**
> A1.2 = 模块式经营台，用户"看"信息再决定点哪；A6 = 对话式，AI 先开口、用户"答"就行。
> 两条都在页面树里，可以对照着看。

## 首页 A1.2 经营版（V14）

老版 A1 是把首页做成「内容工作台」，A1.2 把它换成「今日经营台」：
主语从内容换成「人 + 一段内容主线」，一屏回答三个问题 —— 昨天谁动了、今天发什么、今天跟谁。

> **前提：本产品没有商品模块，也没有交易模块。** 成交发生在微信 / 团购群里，不经过本产品。
> 所以首页不出现商品、价格、SKU；「这一波在推什么」只是团长自己起的一段内容主线，系统当标签用。
> 首页上所有成交数字都由团长自己标注，不来自订单。

| 区块 | 数据来源 | 规则 |
|---|---|---|
| ① 今日经营播报 | `BIZ.yesterday` | 一句话结论 + 四个数 + 一个动作（先跟谁）；替代原 Banner |
| ② 这一波在推什么 | `BIZ.wave` | 8 格阶段条按 phases 展开（讲清楚 / 给证据 / 给理由）；主 CTA 进发布器并带上集数 |
| ③ 待剪 | `BIZ.wave.today` / `.draft` | 今天该出的一条（第几集 / 角度 / 口径 / 时长）+ 卡住的草稿；右上「素材库」进 E2 |
| ④ 待分发 | `BIZ.pending` | 剪好没发的漏损；点「去发」进 S1 |
| ⑤ 今天该跟进 | `BIZ.leads` | 按意向分取前 3，点任意一行展开抽屉（G3.1?u=） |
| ⑥ 团队今天 | `BIZ.team` | 不晒「谁发了什么」，晒「谁的内容带来了成交/高潜」→ 剪同款 |
| ⑦ 团队待办 | `BIZ.todo` | 团队任务降级成一条，不再占首页主位 |

**三个「待」是核心：待剪 → 待分发 → 待跟进。** 对应团长的三个漏损点，缺一环这一波就白做。

**底部一级 tab 改为：首页 / 剪 / 客 / 团队 / 我的。**
`C.tab` 里做了归一化：老页面写 `C.tab("A1")` 仍高亮首页，`E2`/`F1` 归到「剪」，所以 40 多个老页面不用改。

**素材库三个入口**：首页「待剪」右上角、`B1` 剪首页的「我的东西」三宫格（素材库 / 我的作品 / 草稿）、`E2` 本身。

**新增两页**
- `S1` 分发器：选渠道（朋友圈 / 群 / 私聊）→ 三套不同话术 → 带「团长 · 内容 · 渠道」参数的落地页链接。
- `L1` 分享落地页（客户视角）：视频 + 三个要点 + 团购信息 + 「问团长」。**没有下单按钮、没有购物车**，因为成交在微信里完成；页面上标了哪些行为会回传。

**助理（A2）改了角色**：从「任务催办员」换成「经营参谋」。首页右上角 ✦ 进入，
第一屏直接给「今天这三步：剪 1 条 / 发 2 条 / 跟 3 个人」，每个都能点进去。

### 数据从哪来（重要）

**口径只写在 PRD 里**：`../prd/PRD-V2-页面级.md` 第 4 章（首页逐模块：业务逻辑 / 数据来源 / 字段 / 计算口径 / 状态与空态 / 埋点）。UI 稿上不重复这些文字，只保留界面；右侧面板给一行指向 PRD 章节。

代码这边只做两件事：

- `js/data.js` — `window.DATA` 存数据（每块注明接真接口时应来自哪个系统），`window.DERIVE` 存排序/打分/格式化
- 页面 `js/pages/*.js` **不写死任何数字**，只消费 `DERIVE` 的结果

要改"今天必须做"的排序规则只改 `DERIVE.mustDo`；要换数据只改 `DATA`，页面代码不动。接真接口时建议把 `DERIVE` 的算法搬到服务端，前端只展示。

## 怎么改一页

改 `js/pages/` 下对应的那一个文件，保存刷新即可。**其它 23 页完全不受影响**——这就是它比"一版一个大 HTML"值钱的地方。

- 改文案 / 加元素：直接改那个文件里的 HTML 字符串
- 加一个跳转：给元素加 `data-go="目标页ID"`
- 同一个页面换状态：给元素加 `data-set="B2.mode=edit"`
- 目标页还不存在也没关系，会跳到占位页，右侧面板会标红——这正是你要补的地方

## 怎么加一页（3 步）

1. `js/registry.js` 里那一行把状态改成已迁（清单里本来就有 24 页的坑位）
2. 新建 `js/pages/B2.2-shoot.js`：

```js
window.PAGES["B2.2"].render = function (ctx) {
  const C = window.C;
  return `<div class="app">
    ${C.sb()}
    ${C.ab({ title: "随手拍", sub: "拍 3 秒补素材", back: "B2" })}
    <div class="body">…你的内容…</div>
  </div>`;
};
```

3. `index.html` 里加一行 `<script src="js/pages/B2.2-shoot.js"></script>`

刷新，它会自动出现在左侧树、自动参与链路统计。

**为什么皮肤要单独一个文件**：`A8.4.2`（团长预览）和 `L1`（客户点开）必须长得**完全一样**，
两份代码迟早走偏。改 `skins.js` 一处，两边同时变。皮肤里的四个数字位统一带
`.v25-n-like / -cmt / -share / -star` 类名，输入框用 `data-out` 就地改字 —— 不整页重渲染，
否则用户正看着的那一屏会跟着滚动位置一起跑掉。

## 约定

- 手机尺寸固定 **375 × 812**，所有样式按真机写，不要再用缩略图的字号
- 页面根节点是 `<div class="app">`，内部依次是 `状态栏 → 导航栏 → .body（滚动区）→ 底部栏`
- 段卡统一走 `C.seg({...})`，四态：正常 / `on`（当前段）/ `dim`（非当前）/ `miss`（缺素材）
- 所有可点元素都要有 `data-go` 和 `data-label`，否则右侧链路会漏
- 未迁页面 = `PAGES[id].render` 为空，点击进占位页

| 深色数据卡 | 页头下方的关键数字用 `C.hero()`（深蓝渐变 + 白字 + 青色副数据），一页最多一块 |

| 列表 | 一律 `C.li()`：方形圆角缩略图 + 标题 + 两行说明 + 右侧蓝色胶囊动作 |

| 数字口径 | 万/亿用中文单位（8.6万），百分比保留 1 位小数 |

> 禁止：新的自定义色、直角卡片、实心阴影、在深色卡里用灰字。需要新增颜色先加进 `tokens.css`。
